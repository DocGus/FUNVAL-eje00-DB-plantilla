# 06. Arquitectura de la base de datos

## Función del documento

Documentar las decisiones técnicas y los criterios de arquitectura necesarios para implementar, configurar, proteger y mantener la base de datos.

Una base de datos no solamente necesita tablas y relaciones. También requiere decisiones sobre integridad, seguridad, rendimiento, organización, mantenimiento y operación.

Las decisiones deben responder a las necesidades reales del proyecto. No debemos agregar tecnologías o mecanismos solamente porque estén disponibles.

## Conceptos fundamentales

- **Motor de base de datos:** software responsable de almacenar, consultar y administrar información. Ejemplo: PostgreSQL.
- **Arquitectura:** organización de componentes, configuraciones y mecanismos del sistema.
- **Integridad:** mecanismos que garantizan que los datos cumplan las condiciones establecidas.
- **Seguridad:** medidas para proteger los datos y controlar accesos.
- **Rendimiento:** capacidad de responder a consultas y operaciones en tiempos adecuados.
- **Respaldo:** copia de seguridad que permite recuperar información ante pérdidas o incidentes.

## 4. Integridad de los datos

Definir mecanismos para mantener la consistencia y validez de la información.

Tipos de integridad:

1. **Entidad:** cada registro debe identificarse de manera única mediante `PRIMARY KEY`.
2. **Referencial:** las relaciones deben apuntar a registros existentes mediante `FOREIGN KEY`.
3. **Dominio:** los valores deben cumplir condiciones mediante tipos de datos, `NOT NULL`, `CHECK` y otras restricciones.
4. **Unicidad:** determinados valores o combinaciones no deben repetirse mediante `UNIQUE`.

Las restricciones deben derivarse de las reglas del negocio y del modelo relacional.

### 4.3 Eliminación y actualización de registros relacionados

Acciones habituales:

- `CASCADE`: propaga la actualización o eliminación a registros relacionados, según la operación.
- `RESTRICT`: impide la operación cuando existen registros relacionados.
- `NO ACTION`: impide violar la integridad referencial al comprobar la restricción.
- `SET NULL`: establece NULL en la clave foránea, si la columna lo permite.
- `SET DEFAULT`: establece el valor predeterminado, si satisface la restricción.

No utilizar `CASCADE` indiscriminadamente: puede provocar la pérdida de muchos registros.

## 7. Transacciones y concurrencia

Una transacción es un grupo de operaciones que deben ejecutarse como una unidad lógica.

Propiedades ACID:

- **Atomicidad:** todas las operaciones se completan o ninguna se aplica.
- **Consistencia:** se mantienen las reglas de integridad.
- **Aislamiento:** las transacciones concurrentes respetan el nivel de aislamiento establecido.
- **Durabilidad:** los cambios confirmados persisten.

Operaciones:
- `BEGIN`: inicia una transacción.
- `COMMIT`: confirma los cambios.
- `ROLLBACK`: revierte los cambios.

Identificar procesos que requieren varias operaciones coordinadas, como registrar un pedido y sus detalles.

- **7.1:** Identificar operaciones que requieren transacciones.

## 9. Migraciones y control de versiones

Una migración es un cambio versionado en el esquema de la base de datos.

Ejemplos:
- Crear tablas.
- Agregar columnas.
- Modificar restricciones.
- Crear índices.
- Eliminar relaciones.

Ventajas:
- Historial de cambios.
- Reproducción de estructuras en distintos entornos.
- Colaboración entre desarrolladores.
- Control de cambios en producción.

Herramientas posibles: Prisma Migrate, Alembic, Knex migrations y scripts SQL versionados.

Evitar modificaciones manuales sin registro en entornos compartidos.

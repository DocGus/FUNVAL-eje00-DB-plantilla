# Reglas de Negocio

<!--
============================================================
DOCUMENTO: 01_business-rules.md
============================================================

FUNCIÓN:
Este documento identifica, organiza y describe las reglas de negocio
que determinan cómo funciona el sistema y qué condiciones deben cumplirse
durante sus operaciones.

¿QUÉ ES UNA REGLA DE NEGOCIO?
Es una condición, política, restricción o criterio que define cómo debe
comportarse una organización, proceso o sistema.

¿POR QUÉ ES IMPORTANTE?
Las reglas de negocio permiten traducir la lógica de una organización
en condiciones concretas que posteriormente pueden implementarse
mediante la estructura de la base de datos, consultas SQL,
validaciones y lógica de aplicación.

RELACIÓN CON EL DOCUMENTO ANTERIOR:
Las reglas aquí documentadas deben derivarse de los requerimientos
confirmados con el cliente.

IMPORTANTE:
No debemos inventar reglas para completar este documento.
Si una condición no ha sido confirmada, debemos identificarla
como pendiente de validación.

## 2. Clasificación de las reglas de negocio

<!--
OBJETIVO:
Agrupar las reglas según el tipo de condición que representan.

Esta clasificación facilita su análisis y permite identificar
qué reglas podrían necesitar restricciones en la base de datos
y cuáles deberán implementarse en la lógica de la aplicación.

CATEGORÍAS SUGERIDAS:

1. Reglas de integridad:
   Definen condiciones que deben cumplir los datos.
   Ejemplo: el correo electrónico de un usuario debe ser único.

2. Reglas de operación:
   Definen cómo se realizan los procesos.
   Ejemplo: una inscripción solo puede realizarse durante un periodo
   de inscripción autorizado.

3. Reglas de autorización:
   Definen quién puede realizar determinadas acciones.
   Ejemplo: solamente un administrador puede aprobar solicitudes.

4. Reglas de estado:
   Definen las condiciones para cambiar el estado de un elemento.
   Ejemplo: una solicitud aprobada no puede regresar automáticamente
   al estado pendiente.

5. Reglas temporales:
   Definen condiciones relacionadas con fechas, horarios o periodos.
   Ejemplo: una reserva debe realizarse antes de la fecha límite.

6. Reglas de negocio especiales:
   Incluyen políticas particulares que no encajan directamente
   en las categorías anteriores.

IMPORTANTE:
Las categorías son orientativas. Una regla puede relacionarse
con más de una categoría.

## 5. Implicaciones para el diseño de la base de datos

<!--
OBJETIVO:
Identificar qué reglas de negocio pueden y deben representarse
mediante mecanismos de integridad de la base de datos.

NO TODAS LAS REGLAS SE IMPLEMENTAN EN SQL.

Algunas condiciones pueden expresarse directamente mediante:

- PRIMARY KEY: identifica de forma única cada registro.
- FOREIGN KEY: garantiza la integridad referencial.
- NOT NULL: impide valores nulos.
- UNIQUE: evita valores duplicados.
- CHECK: restringe los valores permitidos.
- DEFAULT: establece valores predeterminados.

Otras reglas necesitan lógica adicional en la aplicación,
transacciones, procedimientos almacenados o mecanismos específicos.

La decisión de implementación se realizará durante el diseño
y desarrollo técnico.

IMPORTANTE:
No debemos confundir la regla de negocio con el mecanismo técnico
utilizado para hacerla cumplir.
-->

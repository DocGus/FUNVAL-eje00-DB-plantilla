# Identificación de Entidades y Atributos

<!--

FUNCIÓN:
Identificar las entidades que representan los elementos importantes
del negocio y definir los atributos que necesitamos almacenar
para cada una.

¿POR QUÉ ES IMPORTANTE?
Antes de construir el modelo entidad-relación necesitamos determinar
qué información debe administrar el sistema y cómo organizarla.

Este documento transforma los requerimientos y las reglas de negocio
en una primera estructura conceptual de los datos.

RELACIÓN CON LOS DOCUMENTOS ANTERIORES:

- 00_requirements.md:
  Define qué necesita el cliente y qué problema se desea resolver.

- 01_business-rules.md:
  Define las condiciones y restricciones que gobiernan el negocio.

- 02_entities-and-attributes.md:
  Identifica qué elementos e información necesitamos representar.

IMPORTANTE:
En esta etapa nos concentramos en el análisis conceptual.
Todavía no debemos definir tablas SQL, tipos de datos definitivos
ni escribir instrucciones CREATE TABLE.

============================================================
CONCEPTOS FUNDAMENTALES
============================================================

ENTIDAD:
Elemento del negocio sobre el que necesitamos almacenar información.
Ejemplos: Student, Course, Teacher, Enrollment.

ATRIBUTO:
Característica que describe a una entidad.
Ejemplos: name, email, birth_date.

INSTANCIA:
Registro individual de una entidad.
Ejemplo: un estudiante específico registrado en el sistema.

IDENTIFICADOR:
Atributo o conjunto de atributos que permite distinguir una instancia
de las demás. Posteriormente podrá convertirse en una clave primaria.

DOMINIO:
Conjunto de valores permitidos para un atributo.
Ejemplo: el atributo status podría admitir los valores
'active', 'inactive' y 'suspended'.

============================================================

## 1. Identificación de entidades

<!--
OBJETIVO:
Identificar los elementos del negocio que necesitan ser representados
y cuyos datos deben conservarse en el sistema.

¿CÓMO IDENTIFICAR UNA ENTIDAD?

Buscar sustantivos y conceptos importantes en:
- Los requerimientos.
- Las reglas de negocio.
- Los procesos del negocio.
- Los actores involucrados.
- Los documentos y registros que utiliza actualmente la organización.

No todos los sustantivos representan entidades.
Debemos determinar si el elemento tiene información propia,
identidad y relevancia para el funcionamiento del sistema.

PREGUNTAS DE APOYO:

- ¿Tiene características propias?
- ¿Necesitamos identificarlo individualmente?
- ¿Participa en uno o varios procesos?
- ¿Se relaciona con otras entidades?
- ¿Su información necesita conservarse a lo largo del tiempo?

IMPORTANTE:
No debemos crear entidades únicamente porque aparezcan mencionadas
en los requerimientos. Cada entidad debe tener una justificación.

PREGUNTAS DE APOYO:

- ¿Qué información necesitamos conocer sobre esta entidad?

- ¿Qué información exige alguna regla de negocio?

## 3. Identificación de identificadores

<!--
OBJETIVO:
Determinar cómo podremos distinguir cada instancia de una entidad.

Un identificador debe permitir reconocer un registro sin confundirlo
con otro.

TIPOS DE IDENTIFICADORES:

- Identificador natural:
  Existe en el mundo real o en el contexto del negocio.
  Ejemplo: un número de identificación oficial.

- Identificador artificial o sustituto:
  Se genera específicamente para identificar un registro.
  Ejemplo: un ID autoincremental.

- Identificador compuesto:
  Se forma utilizando dos o más atributos.
  Ejemplo: la combinación de student_id y course_id.

CONSIDERACIONES:
Un dato no debe elegirse como identificador únicamente porque
parezca único en los ejemplos disponibles.
Debemos comprobar que cumple las condiciones de identificación
y que su uso tiene sentido para el negocio.

La decisión definitiva sobre claves primarias se documentará
en el modelo relacional.
-->

## 4. Dominios y restricciones de atributos

<!--
OBJETIVO:
Definir qué valores puede aceptar cada atributo y qué condiciones
deben cumplir.

Un dominio describe el conjunto de valores válidos para un atributo.

EJEMPLOS:

- age: números enteros dentro de un rango definido por el negocio.
- email: dirección de correo con formato válido.
- status: 'active', 'inactive' o 'suspended'.
- birth_date: fecha válida que cumpla las condiciones establecidas.

TIPOS DE RESTRICCIONES QUE DEBEMOS IDENTIFICAR:

- Obligatoriedad: el atributo debe tener un valor.
- Unicidad: no puede repetirse entre registros.
- Rango: el valor debe encontrarse dentro de ciertos límites.
- Formato: debe cumplir una estructura determinada.
- Valores permitidos: solo puede contener opciones definidas.
- Dependencia: su validez puede depender de otros atributos.

IMPORTANTE:
Aquí documentamos las condiciones conceptuales.
Su implementación mediante NOT NULL, UNIQUE, CHECK u otros
mecanismos se realizará posteriormente.
-->

PREGUNTAS DE APOYO:

- ¿Cómo se relaciona una entidad con las demás?

- Uno a muchos (1:N).

IMPORTANTE:

asociativa o tabla intermedia durante el diseño relacional.

## 6. Atributos calculados y derivados

<!--
OBJETIVO:
Identificar atributos cuyo valor puede obtenerse a partir
de otros datos almacenados.

EJEMPLOS:

- age: puede calcularse a partir de birth_date.
- total_amount: puede calcularse sumando los importes de los detalles.
- available_quantity: puede derivarse de las entradas y salidas
  de inventario.

¿POR QUÉ IDENTIFICARLOS?
Almacenar valores derivados puede producir inconsistencias
si los datos originales cambian y el valor calculado no se actualiza.

Sin embargo, en algunos sistemas puede ser necesario conservar
un valor calculado como dato histórico o por razones de rendimiento.

La decisión debe justificarse según las necesidades del negocio.

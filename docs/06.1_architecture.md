Una base de datos no solamente necesita tablas y relaciones.

rendimiento, organización, mantenimiento y operación.

============================================================

MOTOR DE BASE DE DATOS:
Software responsable de almacenar, consultar y administrar

ARQUITECTURA:
Organización de los componentes, configuraciones y mecanismos
que permiten que la base de datos funcione correctamente.

INTEGRIDAD:
Conjunto de mecanismos que garantizan que los datos cumplan

Medidas para proteger los datos y controlar quién puede acceder
a ellos y qué operaciones puede realizar.

RENDIMIENTO:
Capacidad de responder a las consultas y operaciones dentro
de tiempos adecuados para las necesidades del sistema.

RESPALDO:
Copia de seguridad que permite recuperar información ante
pérdidas, errores o incidentes.

## 4. Integridad de los datos

<!--
OBJETIVO:
Definir los mecanismos que permitirán mantener la consistencia
y validez de la información almacenada.

TIPOS DE INTEGRIDAD:

1. Integridad de entidad:
   Cada registro debe poder identificarse de manera única.
   Se garantiza principalmente mediante PRIMARY KEY.

2. Integridad referencial:
   Las relaciones entre tablas deben apuntar a registros existentes.
   Se garantiza mediante FOREIGN KEY.

3. Integridad de dominio:
   Los valores deben cumplir las condiciones de sus atributos.
   Puede garantizarse mediante tipos de datos, NOT NULL,
   CHECK y otras restricciones.

4. Integridad de unicidad:
   Determinados valores o combinaciones no deben repetirse.
   Se garantiza mediante UNIQUE.

IMPORTANTE:
Las restricciones deben derivarse de las reglas de negocio
y de las decisiones del modelo relacional.

### 4.3 Eliminación y actualización de registros relacionados

<!--
OBJETIVO:
Definir qué debe ocurrir cuando se modifica o elimina un registro
que está relacionado con otros registros mediante claves foráneas.

ACCIONES HABITUALES:

- CASCADE:
  Propaga la actualización o eliminación a los registros relacionados,
  según la operación configurada.

- RESTRICT:
  Impide la operación cuando existen registros relacionados.

- NO ACTION:
  Impide que se viole la integridad referencial al comprobar
  la restricción.

- SET NULL:
  Establece NULL en la clave foránea de los registros relacionados,
  siempre que la columna lo permita.

- SET DEFAULT:
  Establece el valor predeterminado de la clave foránea,
  si ese valor satisface la restricción.

IMPORTANTE:
No debemos utilizar CASCADE indiscriminadamente.
Una eliminación puede provocar la pérdida de muchos registros.
La decisión debe responder a las reglas del negocio.

## 7. Transacciones y concurrencia

<!--
OBJETIVO:
Definir criterios para garantizar que las operaciones que modifican
la información se ejecuten de forma consistente.

TRANSACCIÓN:
Grupo de operaciones que deben ejecutarse como una unidad lógica.

PROPIEDADES ACID:

- Atomicidad:
  Todas las operaciones se completan o ninguna se aplica.

- Consistencia:
  La transacción debe mantener las reglas de integridad.

- Aislamiento:
  Las transacciones concurrentes deben ejecutarse sin producir
  resultados incompatibles con el nivel de aislamiento establecido.

- Durabilidad:
  Los cambios confirmados deben persistir.

OPERACIONES HABITUALES:

BEGIN: inicia una transacción.
COMMIT: confirma los cambios.
ROLLBACK: revierte los cambios.

IMPORTANTE:
Debemos identificar los procesos que requieren varias operaciones
coordinadas, como registrar un pedido y sus detalles.
